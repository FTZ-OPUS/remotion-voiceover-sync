# 参考案例：数学/manim QQ群宣传视频 → Remotion 配音对齐（纯配音版）

> 本案例是 `remotion-voiceover-sync` 的第二个实战复盘：**非 PPT 输入、不加数字人**的纯配音对齐用法。
> 展示技能包如何在「已有成片、只需配音对齐」的场景下灵活变通。

## 项目概览

- **输入**：已渲染完成的成片 `math-group-intro-v2.mp4`（无音轨），非 PPT
- **输出**：102 秒、1920×1080、30fps MP4，**纯配音对齐**（无数字人）
- **项目路径**：`~/Desktop/Remotion-Code/math-group-intro/`
- **场景数**：7 个场景（开场/群总览/猫猫同学/凛音同学/muse/吵架看戏/入群引导）
- **群信息**：群名「数学 / manim 编程动画」，群号 `1034827840`

## 变通要点（相对标准工作流的差异）

| 标准工作流 | 本案例变通 |
|------------|-----------|
| 输入 PPT，解压重组场景 | 输入已渲染成片，场景结构已在代码中，直接读 `src/Main.tsx` 拿到场景时长与起始帧 |
| 内嵌 `<Audio>` 到 Remotion 并重新渲染 | **不动画面**，单独生成音轨后用 ffmpeg 混流进已有成片（视频流 copy） |

| 字幕/高亮按句内帧对齐 | 只做**场景级配音定位**，未做文字动画句内重排（本片为宣传视频） |

每段配音设计起始秒 = `starts[i] / 30 + 0.6`：

## 对齐命令（可直接复用）

**裁剪每段开头静音（保留约 0.15s 呼吸感）：**
```bash
ffmpeg -i sN.wav -af "silenceremove=start_periods=1:start_silence=0.05:start_threshold=-50dB" sN_trim.wav
```

**逐帧定点拼接（adelay 把每段钉到对应秒，amix 合并，时长取最长到 102s）：**
```bash
ffmpeg -i s1.wav -i s2.wav ... -i s7.wav -filter_complex \
"[0:a]aformat=sample_rates=44100:channel_layouts=stereo,adelay=600|600[a1];\
 [1:a]aformat=sample_rates=44100:channel_layouts=stereo,adelay=8100|8100[a2];\
 ...
 [6:a]aformat=sample_rates=44100:channel_layouts=stereo,adelay=81600|81600[a7];\
 [a1][a2]...[a7]amix=inputs=7:duration=longest:normalize=0[out]" \
-map "[out]" -t 102 out.wav
```

**混流进成片（视频 copy，保留完整 102s，勿用 -shortest）：**
```bash
ffmpeg -i video.mp4 -i track.wav -map 0:v:0 -map 1:a:0 -c:v copy -c:a aac -b:a 192k out.mp4
```

## 验证结果

- 视频流 102.000s，音频流 99.5s（配音结束，结尾自然静音），保持完整成片时长
- `silencedetect` 各段实际开口点与设计位置偏差 < 0.05s（约 1.5 帧，容差 < 8 帧）
  - 实测开口：S1≈0.65、S2≈8.15、S3≈15.6、S4≈39.15、S5≈55.65、S6≈70.14
- 3 段曾因台词过长溢出场景边界，重新生成精简稿解决（未用变速硬凑）

## 关键决策记录

1. **纯配音、无数字人**：用户明确只要配音对齐，省略数字人口型同步
2. **不重渲染、直接混流**：成片已渲染好，仅单独生成音轨后 mux，省时且不损画面
3. **配音音色**：20岁出头年轻女性，轻柔爽朗阳光可爱，像亲切学姐，语速适中偏轻快，不要播音腔
4. **台词超长即重生成**：不靠 playbackRate/atempo 变速凑时长，删减台词保持音画同步
5. **成品保留完整结尾**：混流不用 `-shortest`，避免把结尾群号停留画面截掉
